# expo-camera `launchScanner` R8 reproducer (Android)

Minimal Expo SDK 58 / expo-camera reproducer for the Android release build bug where
R8 minification strips the ML Kit classes that `CameraView.launchScanner` needs.

- One screen ([src/app/index.tsx](./src/app/index.tsx)) with a single button.
- The button calls `CameraView.launchScanner({ barcodeTypes: ['qr'] })` through
  [src/hooks/useQrCodeScanner.ts](./src/hooks/useQrCodeScanner.ts).
- The scanned QR code is logged to the console and displayed on screen. There is no
  fallback `CameraView` and no custom scanner modal (that one works).

## The bug

`CameraView.launchScanner` relies on the Google code scanner and ML Kit classes being
available under their original names. When R8 obfuscates or removes them in a minified
release build, the GMS scanner setup inside `launchScanner` throws. expo-camera wraps that
whole block in a `try/catch` and rejects with a generic error:

```
Google Play Services is not available on this device. This feature requires Google Play Services.
```

Note that `CameraView.isModernBarcodeScannerAvailable` still reports `true` in that build
(the `Class.forName` check on `com.google.mlkit.vision.barcode.BarcodeScanning` succeeds),
so the flag cannot be used to detect this failure.

Adding the ML Kit / GMS `-keep` rules back makes the same build work.

R8 only runs for release builds (`enableMinifyInReleaseBuilds` in the app config).
Debug builds are never minified, which is why `npm run android` always works.

## App configs

Both configs enable R8 for release builds (`minSdkVersion` 31, Android 12+).

| File | Content | Result |
| --- | --- | --- |
| `app.json` | active config, currently a copy of `app.working.json` | scan works |
| `app.working.json` | minify + `extraProguardRules` keep rules | scan works |
| `app.broken.json` | minify, no `extraProguardRules` | reproduces the bug |

`expo-build-properties` writes the minify flag into `android/gradle.properties` and the
keep rules into `android/app/proguard-rules.pro` **during prebuild**. Switching configs
therefore requires a clean prebuild, otherwise the previous rules stay in place.

## Requirements

- Android device with Google Play services (that supports the GMS scanner)
- Node.js 24, JDK 17, Android SDK.

## Reproduce the bug

From the project root, run:

```powershell
npm install
npm run config:broken # current config
npm run prebuild:android
npm run android:release
```

`npm run android:release` builds the minified release variant, installs it and starts it (no Metro). The release variant is signed with the debug keystore generated by prebuild, so no signing setup is required.

Expected result:

- The screen shows `isModernBarcodeScannerAvailable: true`.
- Tapping "Open QR scanner" results in `launchScanner failed` with the message:
  `Google Play Services is not available on this device. This feature requires Google Play Services.`
- **The Google code scanner UI does not open.**

## Verify the fix

```powershell
npm run config:working
npm run prebuild:android
npm run android:release
```

Expected result:

- The screen shows `isModernBarcodeScannerAvailable: true`.
- **Tapping "Open QR scanner" opens the Google code scanner UI.**

Confirm the rules were applied after prebuild:

PowerShell

```powershell
Select-String -Path android\app\proguard-rules.pro -Pattern "mlkit"
Select-String -Path android\gradle.properties -Pattern "enableMinifyInReleaseBuilds"
```

Linux/macOS

```bash
grep "mlkit" android/app/proguard-rules.pro
grep "enableMinifyInReleaseBuilds" android/gradle.properties
```

With `app.broken.json` the first command prints nothing, with `app.working.json` it
prints the four `-keep` rules.

## Sanity check without minification

To prove the app, the device and Play services are fine, build the regular debug variant:

```powershell
npm run config:working
npm run prebuild:android
npm run android
```

The scanner opens and the QR code is logged. This build is not minified, so it does not exercise the bug. The reproducer is about the release variant.

To run the release variant with minification disabled instead, set `"enableMinifyInReleaseBuilds": false` in the `expo-build-properties` block of `app.json`, run `npm run prebuild:android`, then `npm run android:release`. The scanner opens there as well, which isolates minification as the cause.

## Verified with

- Expo SDK 58.0.17, expo-camera 58.0.12, RN 0.88, Hermes.
- Pixel 9 with Google Play services, Android 17 (SDK 37).
- `assembleRelease` with `minifyReleaseWithR8` enabled.
- Broken build: button shows `Google Play Services is not available on this device.`
- Working build: the Google code scanner opens (verified on the device).
